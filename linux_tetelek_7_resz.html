II/9. Tétel: A rendszerindulás feltételei, lépcsői

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. A bootfolyamat 5 egymásra épülő szakasza (Firmware $\rightarrow$ Bootloader $\rightarrow$ Kernel $\rightarrow$ Initramfs $\rightarrow$ Systemd).
  2. BIOS/MBR vs. UEFI/GPT indítási különbségek.
  3. A `systemd` (PID 1) indítása és a Target-ek szerepe.
  4. A hagyományos SysVinit Runlevel-ek megfeleltetése a modern systemd Target-eknek.

Részletes kidolgozás

1. A Bootfolyamat 5 szakasza

+-----------------------------------------------------------------------+
| 1. FIRMWARE    | BIOS (POST teszt, MBR olvasás) vagy                 |
| (POST)         | UEFI (ESP partíció olvasása, Secure Boot).            |
+----------------+------------------------------------------------------+
| 2. BOOTLOADER  | GRUB2 betöltődik, megjeleníti a menüt, betölti a    |
| (GRUB2)        | vmlinuz kernelt és az initramfs képmást a RAM-ba.    |
+----------------+------------------------------------------------------+
| 3. KERNEL      | A vmlinuz kibontja magát, inicializálja a CPU-t,     |
|                | RAM-ot és a hardvereket, majd elindítja a VFS-t.     |
+----------------+------------------------------------------------------+
| 4. INITRAMFS   | Ideiglenes RAM-diszk lemezvezérlő driverekkel a      |
|                | fizikai gyökér (/) lemez felcsatolásához.            |
+----------------+------------------------------------------------------+
| 5. SYSTEMD     | Elindul az 1-es PID-ű systemd folyamat, párhuzamosan  |
| (PID 1)        | elindítja a szolgáltatásokat az alap Target-ig.      |
+-----------------------------------------------------------------------+

2. Systemd Target-ek vs. Hagyományos SysVinit Runlevel-ek

A modern `systemd` leváltotta a hagyományos szekvenciális SysVinit futási szinteket (Runlevels) függőség-alapú **Target-ekre**:

SysVinit Runlevel Modern systemd Target Cél és működési mód
Runlevel 0 poweroff.target A rendszer teljes leállítása (Power off).
Runlevel 1 / S rescue.target (vagy single-user.target) Egyfelhasználós mentési mód (Single-user mode). Hálózat nélkül, root héjjal.
Runlevel 3 multi-user.target Többfelhasználós hálózati **konzolos / parancssori mód** (Szerverek alapértelmezettje!).
Runlevel 5 graphical.target Többfelhasználós **grafikus mód (GUI)** Display Managerrel (GDM/SDDM) és asztali környezettel.
Runlevel 6 reboot.target A rendszer újraindítása (Reboot).
Tipikus vizsgakérdések és válaszok

K: Mi a szerepe az 1-es PID-ű folyamatnak a Linuxban?
V: Az 1-es PID-ű folyamat (modern rendszereken a `systemd`) a rendszer legelső felhasználói folyamata. Felelős az összes szolgáltatás és démon elindításáért és felügyeletéért, valamint az elárvult (zombi) folyamatok örökbefogadásáért és eltakarításáért.

K: Hogyan kérdezhető le és változtatható meg az alapértelmezett boot Target systemd alatt?
V: Lekérdezés: systemctl get-default. Megváltoztatás: sudo systemctl set-default multi-user.target.

II/10. Tétel: A GRUB működése, konfigurálási lehetőségei

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. A GRUB2 (Grand Unified Bootloader) szerepe és fázisai (Stage 1, 1.5, 2 vs. UEFI ESP).
  2. Konfigurációs fájlok hierarchiája: `/boot/grub/grub.cfg` vs. `/etc/default/grub` vs. `/etc/grub.d/`.
  3. A GRUB konfiguráció frissítése (`update-grub`).
  4. Telepítés és mentési műveletek az interaktív GRUB parancssorból (`grub>`).

Részletes kidolgozás

1. A GRUB2 fázisai

  • Hagyományos MBR/BIOS indításnál:**
    • Stage 1 (`boot.img`): Az MBR első 446 bájtjában lévő apró kód, aminek egyetlen feladata a Stage 1.5 betöltése.
    • Stage 1.5 (`core.img`): Az MBR és az 1. partíció közötti üres szektorokban tárolódik. Tartalmazza az alapvető fájlrendszer-drivert.
    • Stage 2: A `/boot/grub/` könyvtárból betölti a teljes GRUB2 modult, beolvassa a konfigurációt és megjeleníti a mentüt.
  • Modern UEFI indításnál:** Nincsenek Stage-ek. Az UEFI firmware közvetlenül beolvassa az ESP (EFI System Partition - FAT32) partícióról a `/EFI/BOOT/BOOTX64.EFI` binárist.

2. A GRUB2 konfigurációs struktúrája

KRITIKUS VIZSGAPONT: A `/boot/grub/grub.cfg` fájlt SOHA NEM SZABAD KÉZZEL SZERKESZTENI!

  • /etc/default/grub: A rendszeradminisztrátor által szerkeszthető fő konfigurációs állomány.
    • GRUB_DEFAULT=0: Alapértelmezett menüpont indexe.
    • GRUB_TIMEOUT=5: Várakozási idő másodpercben a menüben.
    • GRUB_CMDLINE_LINUX_DEFAULT="quiet splash": A kernelnek átadott indítási opciók.
  • /etc/grub.d/: Generáló szkriptek könyvtára (`00_header`, `10_linux`, `40_custom`).
  • /boot/grub/grub.cfg: A generált végleges konfigurációs fájl. A sudo update-grub (vagy grub2-mkconfig -o /boot/grub/grub.cfg) parancs hozza létre a `/etc/default/grub` és a `/etc/grub.d/` alapján.

3. Helyreállítás az interaktív GRUB parancssorból (`grub>`)

Ha a rendszer nem tud bebootolni, a GRUB parancssorból kézzel is megadhatók az indítási paraméterek:

grub> ls                                     # Partíciók kilistázása (pl. (hd0,gpt1))
grub> set root=(hd0,gpt1)                     # Gyökérpartíció kijelölése
grub> linux /boot/vmlinuz-6.8.0 root=/dev/sda1 # Kernel és root lemez megadása
grub> initrd /boot/initrd.img-6.8.0          # Initramfs megadása
grub> boot                                   # Indítás
Tipikus vizsgakérdések és válaszok

K: Melyik fájlt kell szerkeszteni a GRUB alapértelmezett várakozási idejének módosításához?
V: A **`/etc/default/grub`** fájlt kell szerkeszteni (a `GRUB_TIMEOUT` sor módosításával), majd le kell futtatni a `sudo update-grub` parancsot a módosítások érvényesítéséhez.

K: Hogyan telepíthető újra a GRUB2 rendszertöltő az MBR-be/lemezre?
V: A `sudo grub-install /dev/sda` paranccsal.

II/11. Tétel: Szolgáltatások kezelése és automatikus indítása

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. A `systemd` mint szolgáltatáskezelő (Service Manager).
  2. A Unit fájlok felépítése (`.service`) és a 3 fő szekció ([Unit], [Service], [Install]).
  3. Unit fájlok helye: `/lib/systemd/system/` vs. `/etc/systemd/system/`.
  4. A `systemctl` vezérlőparancs teljes eszköztára (futási állapot, boot engedélyezés, mask).

Részletes kidolgozás

1. A `systemd` `.service` Unit fájlok felépítése

A `systemd`-ben minden szolgáltatást egy `.service` kiterjesztésű deklaratív konfigurációs fájl ír le (példa: `custom.service`):

[Unit]
Description=Saját Alkalmazás Szolgáltatás
After=network.target syslog.target    # Csak a hálózat elindulása után indulhat
Requires=postgresql.service           # Szoros függőség: ha a Postgres leáll, ez is leáll

[Service]
Type=simple                           # Indítási típus (simple, forking, oneshot, notify)
ExecStart=/usr/local/bin/myapp        # Az elindítandó bináris abszolút útja
ExecReload=/bin/kill -HUP $MAINPID    # Újratöltéskor lefutó parancs
Restart=on-failure                    # Hiba esetén automatikusan újraindítja
User=www-data                         # Milyen felhasználóként fusson

[Install]
WantedBy=multi-user.target            # Az 'enable' hatására ehhez a targethez linkelődik

2. Unit fájlok könyvtár-hierarchiája

  • `/lib/systemd/system/` (vagy `/usr/lib/...`):** A csomagkezelő (apt/dnf) által telepített gyári unit fájlok helye. **Kézzel módosítani tilos!**
  • `/etc/systemd/system/`:** A rendszeradminisztrátor egyedi vagy felülbírált unit fájljainak helye. Az itt lévő fájlok **elsőbbséget élveznek** a gyári fájlokkal szemben!

3. Szolgáltatáskezelés a `systemctl` paranccsal

Parancs Funkció és működés
systemctl status ssh Megmutatja az `ssh` szolgáltatás állapotát (active/inactive, PID, memóriahasználat, utolsó logok).
systemctl start ssh Azonnal elindítja a szolgáltatást az aktuális munkamenetben (a RAM-ban).
systemctl stop ssh Leállítja a futó szolgáltatást.
systemctl restart ssh Újraindítja a szolgáltatást (stop majd start).
systemctl reload ssh Újraolvastatja a konfigurációt a szolgáltatással **leállítás nélkül** (SIGHUP).
systemctl enable ssh **Engedélyezi az automatikus indítást** a következő boot során (szimbolikus linket hoz létre).
systemctl disable ssh **Törli az automatikus boot indítást** (eltávolítja a szimbolikus linket).
systemctl enable --now ssh **Egyetlen lépésben** engedélyezi a boot indítást ÉS azonnal el is indítja a szolgáltatást!
systemctl mask ssh **Teljesen letiltja** a szolgáltatást (a `/dev/null`-ra linkeli), így kézzel vagy függőségként sem indítható el.
systemctl daemon-reload Újraolvassa a `/etc/systemd/system/` könyvtár módosított unit fájljait.
Tipikus vizsgakérdések és válaszok

K: Mi a különbség a `systemctl start` és a `systemctl enable` parancsok között?
V: A `systemctl start` a szolgáltatást **azonnal elindítja az aktuális munkamenetben**, de a gép újraindítása után nem indul el. A `systemctl enable` a **jövőbeli boot folyamatokhoz** állítja be az automatikus indítást (szimbolikus linket hozva létre), de az aktuálisan futó állapotot nem változtatja meg.

K: Mi a szerepe a `systemctl mask` parancsnak?
V: A `mask` a szolgáltatás unit fájlját a `/dev/null`-ra linkeli át, megakadályozva, hogy azt akár kézzel (`start`), akár egy másik szolgáltatás függőségeként el lehessen indítani.

II/12. Tétel: A hálózat működési feltételei, hálózati interfészek, konfigurálási és tesztelési parancsok

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. A hálózati kommunikáció 4 alapvető feltétele.
  2. Interfész-elnevezési konvenciók (Hagyományos vs. Kiszámítható nevek: `eno1`, `enp3s0`).
  3. Konfigurálás: Modern `iproute2` (`ip`) vs. Hagyományos `net-tools` (`ifconfig`, `route`).
  4. Hálózatdiagnosztika és tesztelő parancsok (`ping`, `traceroute`, `ss -tulpn`, `dig`, `nc`).

Részletes kidolgozás

1. A Hálózati működés 4 alapvető feltétele

  1. Aktív Interfész (Link UP):** Működő hálózati kártya és kernel driver, amely aktív állapotban van.
  2. IP-cím és Alhálózati maszk:** Egyedi azonosító és a helyi alhálózat (Broadcast domain) határai.
  3. Alapértelmezett Átjáró (Default Gateway):** A helyi router IP-címe a távoli hálózatok eléréséhez.
  4. Névfeloldás (DNS Server):** DNS szerverek címei (pl. `/etc/resolv.conf`) a domain nevek IP-re fordításához.

2. Konfiguráció: Modern (`iproute2`) vs. Hagyományos (`net-tools`)

A modern Linux disztribúciókban a `net-tools` csomag (`ifconfig`, `route`, `netstat`) elavult (`deprecated`). Helyette a **`iproute2`** csomag (`ip`, `ss`) a szabvány:

Művelet Modern `iproute2` parancs Hagyományos `net-tools` parancs
IP-címek lekérdezése ip addr show (vagy ip a) ifconfig
Interfész be/kikapcsolás ip link set dev enp3s0 up / down ifconfig enp3s0 up / down
IP-cím hozzáadása ip addr add 192.168.1.50/24 dev enp3s0 ifconfig enp3s0 192.168.1.50 netmask 255.255.255.0
Útvonaltábla megtekintése ip route show route -n vagy netstat -rn
Default Gateway megadása ip route add default via 192.168.1.1 route add default gw 192.168.1.1

3. Hálózatdiagnosztikai parancsok

  • ping -c 4 8.8.8.8: ICMP Echo kérések küldése az elérhetőség és válaszidő (RTT) tesztelésére.
  • traceroute google.com / tracepath google.com: Megmutatja a köztes útválasztókat (hop-okat) a célállomásig.
  • mtr google.com: Valós időben frissülő kombinált ping és traceroute diagnosztika.
  • `ss -tulpn` (Socket Statistics - NAGYON GYAKORI VIZSGAPARANCS!):** Megmutatja a nyitott portokat.
    • -t: TCP socketek, -u: UDP socketek, -l: Hallgatózó (Listening) portok, -p: Folyamat és PID kijelzése, -n: Numerikus IP és portszámok.
  • dig google.com / dig @8.8.8.8 google.com: Részletes DNS lekérdezés a névfeloldás tesztelésére.
  • nc -zv 192.168.1.1 80 (Netcat): Teszteli, hogy a célgépen a 80-as TCP port nyitva van-e.
Tipikus vizsgakérdések és válaszok

K: Melyik a 4 alapvető feltétel a hálózati kommunikációhoz?
V: 1. Működő interfész (`Link UP`), 2. Érvényes IP-cím és alhálózati maszk, 3. Alapértelmezett átjáró (Default Gateway), 4. Működő DNS szerver.

K: Mit jelentenek a kapcsolók az `ss -tulpn` parancsban?
V: `-t`: TCP protokollok, `-u`: UDP protokollok, `-l`: hallgatózó (Listening) portok, `-p`: a portot lefoglaló folyamat neve és PID-je, `-n`: numerikus IP-címek és portszámok megjelenítése névfeloldás nélkül.
