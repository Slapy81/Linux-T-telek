II/13. Tétel: Hálózati kiszolgálók és speciális hálózati képességek Linux alatt

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. Alapvető hálózati kiszolgálók (DHCP, DNS, Web, Samba, NFS, SSH).
  2. Csomagszűrés és Tűzfal: A Netfilter keretrendszer (`iptables` vs. `nftables`).
  3. Hálózati címfordítás (NAT: SNAT / Masquerading vs. DNAT / Port Forwarding).
  4. IP Forwarding, Network Bonding, Bridging és Network Namespaces.

Részletes kidolgozás

1. Alapvető hálózati kiszolgálók

  • DHCP Szerver (UDP 67/68):** `isc-dhcp-server`, `dnsmasq`. Automatikus IP-cím, maszk, átjáró és DNS osztás.
  • DNS Szerver (UDP/TCP 53):** `bind9`, `unbound`. Névfeloldás (A, AAAA) és reverz feloldás (PTR).
  • Webszerver:** `apache2`, `nginx`. HTTP (80) és HTTPS (443) kiszolgálás. Az Nginx kiváló Reverse Proxy is.
  • Samba Szerver (TCP 445):** SMB/CIFS fájl- és nyomtatómegosztás **Linux és Windows gépek között**, AD DC integrációval.
  • NFS Szerver (TCP 2049):** Network File System. POSIX-kompatibilis, nagy sebességű fájlmegosztás **kizárólag Linux/Unix gépek között**.
  • OpenSSH Szerver (TCP 22):** Titkosított távoli shell elérés, pubkey hitelesítés, SCP/SFTP és port alagutazás (Tunneling).

2. Netfilter, Tűzfal és NAT

A **Netfilter** a Linux kernelen belüli csomagszűrő keretrendszer:

  • `iptables` / `nftables`:** A Netfilter felhasználói felületei.
    • `PREROUTING`: Csomag beérkezésekor lefutó lánc (ideális **DNAT / Port Forwarding** végrehajtására).
    • `POSTROUTING`: Csomag kiküldése előtt lefutó lánc (ideális **SNAT / Masquerading** végrehajtására).
  • IP Forwarding (Routing feltétel!):** sysctl -w net.ipv4.ip_forward=1
  • Bonding vs. Bridging:**
    • Network Bonding: Több kártya összefogása sávszélesség-növelésre vagy hibatűrésre (Failover).
    • Network Bridge (`br0`): Memóriabeli szoftveres switch virtuális gépek (KVM) és konténerek fizikai hálózatra kötésére.
  • Network Namespaces (`ip netns`):** Elszigetelt hálózati stack-ek (Docker hálózatkezelés alapja).
Tipikus vizsgakérdések és válaszok

K: Mi a különbség az NFS és a Samba fájlmegosztó szolgáltatások között?
V: Az NFS egy natív Unix/Linux hálózati fájlrendszer Linux gépek közötti nagy sebességű megosztásra. A Samba az SMB/CIFS protokollt valósítja meg, így Linux és Windows rendszerek közötti fájlmegosztásra szolgál.

K: Mi a feltétele annak, hogy egy Linux gép routerként továbbítsa a csomagokat az interfészei között?
V: Engedélyezni kell a kernelben az IP továbbítást: net.ipv4.ip_forward = 1.

II/14. Tétel: Az X Window System felépítése, működése

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. Az X11 (X Window System) alapelvei: Hálózati transzparencia és Mechanizmus vs. Házirend szétválasztása.
  2. Az X11 Ügyfél-Kiszolgáló (Client-Server) architektúrája.
  3. A grafikus környezet rétegei (Display Manager, Window Manager, Widget Toolkits, DE).
  4. Az X11 korlátai és a modern **Wayland** architektúra.

Részletes kidolgozás

1. Az X11 Alapelvei és a Client-Server Modell

  • Hálózati transzparencia:** Az X Kliens (alkalmazás) és az X Szerver (megjelenítő) futhat ugyanazon a gépen vagy hálózaton összekötött eltérő gépeken is.
  • Mechanizmus vs. Házirend:** Az X11 csak a **mechanizmust** adja (grafikus primitívek rajzolása, beviteli események továbbítása), de nem határozza meg a **házirendet** (hogyan nézzen ki egy ablak, hol legyen a gomb). Ezt a felsőbb rétegek végzik.
  • X Szerver (pl. Xorg):** A **felhasználó fizikai gépén fut**, kezeli a kijelzőt, billentyűzetet és egeret.
  • X Kliens:** Maga a grafikus alkalmazás (pl. Firefox), ami az X11 hálózati protokollon keresztül küld rajzolási utasításokat a szervernek.

2. A Grafikus környezet rétegei és a Wayland

  • Display Manager:** Grafikus bejelentkező felület (GDM, SDDM, LightDM).
  • Window Manager (WM):** Az ablakok elrendezéséért, keretéért és átméretezéséért felel (i3wm, Openbox, Mutter, KWin).
  • Widget Toolkits:** Rajzolási elemkészletek a fejlesztőknek (GTK, Qt).
  • Munkakörnyezet (DE):** Egységes csomag (GNOME, KDE Plasma, XFCE).
  • Wayland:** A modern utód. Megszünteti a különálló X szervert: az **Ablakkezelő (Compositor) maga a megjelenítő**. Képtörés-mentes (no screen tearing), közvetlen rajzolású és szigorúan biztonságos elszigetelést nyújt az ablakok között.
Tipikus vizsgakérdések és válaszok

K: Miért mondjuk, hogy az X11 Client-Server architektúrájú és hol fut az X Szerver?
V: Mert szétválasztja a rajzoló alkalmazáskódot és a kijelző hardvert. Az **X Szerver a felhasználó helyi fizikai gépén fut**, mert ő kezeli a helyi képernyőt és beviteli eszközöket.

II/15. Tétel: A Linux disztribúció fogalma, a disztribúciók általános jellemzői

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. A Linux disztribúció fogalma (Kernel + GNU + Init + Csomagkezelő + GUI).
  2. Csomagkezelő családok (.deb, .rpm, pacman).
  3. Kiadási modellek: Fix kiadásos (Fixed release) vs. Gördülő kiadásos (Rolling release).
  4. Főbb disztribúció-családok (Debian/Ubuntu, Red Hat/RHEL/Fedora, Arch, SUSE).

Részletes kidolgozás

1. A Disztribúció fogalma és Összetevői

A **Linux önmagában csak a rendszermag (Kernel)**. A **Linux disztribúció** egy olyan teljes, használatra kész operációs rendszer, amely a kernel köré integrálja a `glibc` C könyvtárat, a GNU rendszereszközöket, az Init rendszert (systemd), a csomagkezelőt, a grafikus környezetet és a felhasználói szoftvereket.

2. Kiadási modellek összehasonlítása

Szempont Fix Kiadásos (Fixed / Point Release) Gördülő Kiadásos (Rolling Release)
Működés Ciklikus főverziók (pl. 2 évente). A szoftververziók rögzítettek, csak biztonsági frissítéseket kapnak. Nincsenek főverziók. A rendszer folyamatosan frissül a legújabb szoftverekre.
Előny / Hátrány **Rendkívül stabil**, tesztelt. Hátránya: régebbi szoftververziók. **Mindig a legfrissebb szoftverek**. Hátránya: nagyobb a frissítési törések kockázata.
Példák Debian Stable, Ubuntu LTS, Red Hat Enterprise Linux (RHEL). Arch Linux, openSUSE Tumbleweed, Manjaro.
Tipikus vizsgakérdések és válaszok

K: Mi a különbség a Fix kiadású és a Gördülő kiadású disztribúciók között?
V: A Fix kiadású disztribúciók (pl. Debian, Ubuntu LTS) rögzített főverziókkal dolgoznak a maximális stabilitásért. A Gördülő kiadású disztribúciókban (pl. Arch Linux) nincsenek főverziók, a rendszer megszakítás nélkül frissül a legfrissebb csomagokra.

II/16. Tétel: Csomagkezelés Linux operációs rendszerben, csomagok fajtái és kezelésük, frontend-ek

A felelet szerkezeti vázlata (Fejben tartható váz):
  1. A csomagkezelés fogalma, célja és a szoftvertárolók (Repositories).
  2. Csomagok fajtái: Hagyományos bináris (`.deb`, `.rpm`), Forráskód alapú és Disztribúciófüggetlen (Flatpak, Snap, AppImage).
  3. A csomagkezelés rétegei: Alacsony szintű (`dpkg`, `rpm`) vs. Magas szintű (`apt`, `dnf`).
  4. Csomagkezelő Frontend-ek (TUI: `aptitude`, GUI: Synaptic, GNOME Software).

Részletes kidolgozás

1. Csomagok Fajtái és Formátumai

  • Hagyományos bináris csomagok (`.deb`, `.rpm`):** Előre lefordított csomagok adott disztribúcióra és architektúrára. A közös rendszerkönyvtárakra támaszkodnak.
  • Forráskód alapú csomagok:** A szoftver forráskódját tartalmazzák (`.tar.gz`), amit a helyi gépen kell lefordítani (pl. Gentoo `emerge`).
  • Disztribúciófüggetlen, homokozósított (Sandboxed) csomagok:**
    • Flatpak:** Asztali GUI alkalmazásokra fókuszál. Minden függőséget magában foglal, izoláltan fut (Flathub).
    • Snap:** A Canonical (Ubuntu) rendszere szerveres és asztali csomagokhoz. Csatolt SquashFS lemezképként fut.
    • AppImage:** Telepítést és root jogot **nem igénylő**, egyetlen futtatható hordozható bináris.

2. Alacsony vs. Magas szintű csomagkezelők

Család Csomagkiterjesztés Alacsony szintű eszköz (NINCS függőségkezelés!) Magas szintű eszköz (VAN automatikus függőségkezelés!)
Debian / Ubuntu / Mint .deb dpkg -i csomag.deb apt install csomag (vagy apt-get)
Red Hat / RHEL / Fedora .rpm rpm -ivh csomag.rpm dnf install csomag (régebben yum)
Arch Linux / Manjaro .pkg.tar.zst pacman (integrált) pacman -S csomag (+ AUR)

3. Csomagkezelő Frontend-ek

  • TUI (Szöveges felület):** `aptitude` (Debian/Ubuntu ncurses felület intelligens függőségfeloldóval).
  • GUI (Grafikus felület):** Synaptic Package Manager (részletes GTK csomagkezelő), GNOME Software, KDE Discover, YaST (openSUSE).
Tipikus vizsgakérdések és válaszok

K: Mi a különbség a `dpkg` és az `apt` parancsok között?
V: A `dpkg` az alacsony szintű csomagkezelő, amely csak egyetlen helyi `.deb` fájlt tud telepíteni, de nem éri el a hálózati tárolókat és **nem tudja feloldani a hiányzó függőségeket**. Az `apt` a magas szintű eszköz, amely a tárolókból automatikusan felkutatja és letölti a hiányzó függőségeket is.

K: Mi a fő előnye a Flatpak/Snap csomagoknak a hagyományos `.deb`/`.rpm` csomagokkal szemben?
V: A Flatpak és Snap csomagok az alkalmazást és annak **összes függőségét egyetlen izolált (sandbox-olt) csomagban** tartalmazzák, így tetszőleges Linux disztribúción módosítás és függőségi konfliktusok nélkül futtathatók.
